# Contract: Client Google sign-in (app side)

Pure logic is unit-tested with Jest (node env, no React Native). `.tsx` files only render. Extends
[spec 005 client-auth.md](../../005-user-auth/contracts/client-auth.md).

## Modules

| Module | Responsibility | Tested by |
|--------|----------------|-----------|
| `src/services/auth/client.ts` (extended) | `providers()`, `googleStart()` → `{ url, verifier }`, `googleExchange(ticket, verifier, deviceId)`; new error codes `google_disabled`, `invalid_ticket` | `tests/contract/authClient.test.ts` |
| `src/services/auth/googleFlow.ts` | pure state machine + deep-link parser (below) | `tests/unit/auth/googleFlow.test.ts` |
| `src/services/auth/service.ts` (extended) | `startGoogle(openUrl)`, `finishGoogle(params)`; same state, session and attribution effects as `verify` | `tests/unit/auth/service.test.ts` |
| `src/services/auth/messages.ts` (extended) | Google error → `{ title, hint }` | `tests/unit/auth/messages.test.ts` |
| `app/sign-in.tsx`, `app/settings.tsx` | render the button, handle the return link, adjust the delete confirmation text | manual (quickstart) |

**Note**: the app does no cryptography for this feature. It has no CSPRNG (device ids use `Math.random`) and `expo-crypto` would add a native
module, so the verifier is generated by the server (`start`) and the app only stores and returns it.

## States (`googleFlow.ts`)

```text
idle --tap "Continue with Google"--> starting   (POST start; verifier stored; browser opened)
starting --network/503--> idle(error)
starting --browser opened--> waitingForReturn
waitingForReturn --deep link ?ticket--> exchanging --200--> done(email)
exchanging --invalid_ticket--> idle(error: expired)
exchanging --network/5xx--> idle(error: network)        [ticket may still be valid: "Try again" re-opens the browser]
waitingForReturn --deep link ?error=cancelled--> idle   [no error message]
waitingForReturn --deep link ?error=<other>--> idle(error)
any --app comes back without a link (learner closed the browser)--> idle   [after 10 min the pending verifier is dropped]
```

One attempt at a time: tapping while `starting`/`waitingForReturn`/`exchanging` is ignored.

## Deep link

`earwarrior://sign-in?ticket=<t>` | `earwarrior://sign-in?error=<code>`. Parsed by `parseGoogleReturn(params)` → `{ kind:'ticket', ticket } | { kind:'error', code } | null`; unknown or oversized values → `null` (ignored).

## Error copy (what happened + what to do)

| Code | Title | Hint |
|------|-------|------|
| `cancelled` | *(none — silent)* | |
| `unverified_email` | Google hasn't verified that email | Verify it in your Google account, or sign in with an email code instead |
| `expired` / `invalid_ticket` | That sign-in took too long | Tap "Continue with Google" to try again |
| `google_failed` | Google sign-in didn't work | Try again, or sign in with an email code |
| `google_disabled` | Google sign-in isn't available right now | Use the email code — you can keep practising either way |
| `network` | Can't reach the server | You can keep practising; try signing in later |
| *(no browser can open the link)* | Couldn't open your browser | Open Chrome once, or sign in with an email code |

## Screens

- **Sign-in**: under the heading, a "Continue with Google" button (Google's branding: white/neutral button with the "G" mark, label exactly "Continue with Google", accessible label the same) above a divider "or use an email code" and the existing email field. Hidden when `providers().google` is false or the call failed. Skip is unchanged.
- **Settings → Account**: unchanged; "Delete account" confirmation gains "Your Google account is not changed."
